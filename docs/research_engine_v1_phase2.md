# Research Engine V1 — Phase 2: Descriptive Statistics

## Overview

Research Engine Phase 2 introduces a generic Descriptive Statistics Engine to answer:
> "What does the population of realized outcomes look like?"

This is a **descriptive** layer. It does not compute alpha, perform statistical significance testing, or evaluate trading strategies. It simply summarizes the mathematical properties of the forward outcome populations produced by Phase 1.

## Architecture

The Statistics Engine operates entirely downstream of Phase 1:
`ResearchSpec` → `EventEngine` → `OutcomeEngine` → **`StatisticsEngine`** → `ResultStore`

**Core Components:**
- `statistics_engine.py`: Implements deterministic math and grouping logic.
- `models.py`: Adds `StatisticsResult`, `DescriptiveStats`, `ReturnStats`, `SampleQuality`, and `Quantiles`.

## Statistics Contract

For every defined grouping dimension, the engine produces one `StatisticsResult` containing:

### 1. Sample Integrity (`SampleQuality`)
- `event_count`: Total raw events detected.
- `valid_outcome_count` (N): Total observations with valid numeric outcomes (excluding NaN/Inf).
- `missing_outcome_count`: Observations where the price was missing at T or T+H.
- `insufficient_future_data_count`: Observations where T+H exceeded the dataset.
- `invalid_outcome_count`: Observations that resulted in NaN or Infinity.

**Rule:** `N = valid_outcome_count`. Only these `N` observations enter mathematical calculations.

### 2. Central Tendency & Dispersion (`DescriptiveStats`)
- `mean`: Standard arithmetic mean. `sum(x) / N`
- `median`: Exact median.
- `std`: Sample standard deviation with `ddof=1`. Returns `null` if `N < 2`.
- `min`: Minimum valid value.
- `max`: Maximum valid value.

### 3. Quantiles (`Quantiles`)
An explicit, fixed linear interpolation method is used to guarantee reproducibility across library versions.
For a sorted array `X` of size `N`:
1. `index = (N - 1) * p`
2. `lower = floor(index)`, `upper = lower + 1`
3. `value = X[lower] * (1 - fraction) + X[upper] * fraction`

Computed quantiles: `p01, p05, p10, p25, p50, p75, p90, p95, p99`

### 4. Return Semantics (`ReturnStats`)
Applicable only when `outcome_type == OutcomeType.RETURN_LIKE`:
- `win_rate`: `count(x > 0) / N`. (Exactly zero is a non-win).
- `positive_count`, `negative_count`, `zero_count`.
- `mean_positive`: `mean(x | x > 0)`.
- `mean_negative`: `mean(x | x < 0)`.
- `largest_gain`: equivalent to `max`.
- `largest_loss`: equivalent to `min`.

### 5. Grouping
Statistics are computed across explicitly specified dimensions:
- `overall`: All events pooled.
- `symbol`: Grouped by individual symbol.
- `horizon`: Grouped by forward horizon.
- `symbol_horizon`: Grouped by (symbol, horizon) pairs.

No hidden weighting schemes (e.g. market-cap weighting) are applied. All aggregates are simple observation-level metrics.

## Empty and Small Sample Behaviour

- **`N = 0`**: All metrics (`mean`, `std`, `win_rate`, quantiles) return `null`. The engine never fabricates `0.0`.
- **`N = 1`**: `mean`, `median`, `min`, `max`, and quantiles return the single value. `std` returns `null`.
- **NaN/Inf**: Excluded from `N` and logged in `invalid_outcome_count`.

## Determinism & Persistence

- All inputs are sorted explicitly prior to calculation to guarantee ordering determinism.
- Duplicates generated by Phase 1 are treated as distinct observations unless deduplicated upstream.
- Results are saved to `data/research/{research_id}/statistics/statistics.jsonl`.
- Idempotency key: `(research_id, grouping_type, symbol, horizon, outcome_name)`. Repeated executions with identical specs will overwrite or skip, but never duplicate historical summary rows.

## Known Limitations (Intentionally Deferred)
- **Statistical Significance**: No p-values, t-tests, or bootstrapping.
- **Advanced Grouping Weights**: No inverse-volatility or liquidity weighting.
- **Financial Ratios**: No Sharpe, Sortino, Calmar, or Information Ratio metrics.
